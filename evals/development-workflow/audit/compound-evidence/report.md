## Attribution rule

A successful `&&` chain with terminal exit 0 confirms its parts ran successfully. The recorded tool result still has only one aggregate stdout/status, so it does *not* prove which part produced which line. The v5 evaluator now recognizes a probe only from an isolated app invocation with matching inputs, complete output, and status. It does not distribute aggregate lines across invocations based on expected answers or line counts. The separate-launch regression is in the contract tests. The audit package also contains the fixed executable counterexample at [`counterexample/app.py`](counterexample/app.py), its expected observations at [`counterexample/expected.json`](counterexample/expected.json), and a reproducer that runs the fixture—not any recorded trace command—and verifies both observed process boundaries and the evaluator's `UNCONFIRMED` attribution.

The third command segment is `python3 app.py Alice`, not `python3 app.py`. The full trace contains no omitted tool events, and the independent parser found no unsupported terminal command that could hide another launch.
