# Source ↔ Runtime Sync

Use this file when changing the `flight-calendar-ics` implementation, tests, templates, references, schemas, scripts, or assets rather than only generating a one-off `.ics` file.

## Why this matters

This skill has two operational copies:

- source repository copy: `/home/konstantin/Hermes-Backup/hermes/skills/productivity/flight-calendar-ics`
- runtime copy loaded by Hermes: `/home/konstantin/.hermes/skills/productivity/flight-calendar-ics`

Treat source → runtime synchronization as a deliberate side effect. Do not silently overwrite runtime-only references or generated artifacts.

## Safe sync pattern

1. Work in the source repository copy and check branch/status before edits.
2. Keep the change scoped to the skill files relevant to the task.
3. Run relevant tests from the source copy.
4. Before syncing, inspect runtime-only files. If a runtime-only reference contains durable knowledge, copy it into source and include it in the commit rather than deleting it during sync.
5. Back up the runtime skill directory before replacing it.
6. Sync source → runtime.
7. Remove generated artifacts from both copies (`__pycache__/`, `*.pyc`, transient outputs).
8. Verify parity by comparing file sets and file contents of source and runtime. Expected result after a clean sync:
   - no `only_source` files;
   - no `only_runtime` files;
   - no changed files;
   - no generated bytecode artifacts.
9. Only then finalize the scoped commit.

## Verification evidence to report

For maintenance tasks, final status should include:

- branch and commit hash;
- test command and pass/fail count;
- source/runtime parity result;
- runtime backup path;
- generated artifact count after cleanup;
- explicit note whether push was performed.

## Pitfalls

- Do not treat runtime sync as background housekeeping; it changes what Hermes will load in future sessions.
- Do not delete runtime-only references just because they are absent from source; first decide whether they are durable enough to promote into source.
- When a runtime-only reference captures reusable carrier/API discovery, promotion to source is not enough by itself. Decide whether behavior should become executable; if yes, add/extend the provider script and single CLI entrypoint with RED→GREEN tests before syncing runtime.
- Do not leave `__pycache__` or `*.pyc` files in runtime skill directory after running tests or scripts.
- Do not commit broad repository changes while maintaining this skill; keep commits scoped to the skill and its tests/docs/assets.
