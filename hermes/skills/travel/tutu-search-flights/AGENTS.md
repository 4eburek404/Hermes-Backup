# tutu-search-flights — навигатор

Поиск авиабилетов через Tutu MCP. Скилл для Hermes, внутри скилла — CLI, который
вызывает агент. CLI подключается к MCP-серверу как клиент; сам он MCP-сервером не является
и к сайтам авиакомпаний не ходит.

Версия 0.1 в разработке. Рабочей команды пока нет.

## Команды

```bash
make check        # ворота: всё разом. Перед словом «готово»
make arch         # архитектурные тесты: чистота ядра, направление зависимостей
make test         # юнит-тесты
make lint         # ruff
make types        # mypy --strict
make docs-check   # команда, названная в документации, существует
make discover     # переснять спецификацию Tutu MCP в fixtures/
```

## Как сдаётся работа

Сначала спека, потом тесты, потом код. Для любого нового поведения: спека → шаги, пока
не покраснеет по делу → красные юнит-тесты → реализация снизу вверх → `make check` →
документы в том же изменении.

Никогда не заявлять «работает» без запуска команды и её вывода.

## Слои

Зависимости направлены только вниз, обратных импортов нет.

| Слой | Где | Природа |
|---|---|---|
| core | `src/tutu_search_flights/core/` | чисто: без сети, файлов, часов, печати |
| mcp | `src/tutu_search_flights/mcp/` | единственное место про MCP: транспорт, вызов, разбор сырого JSON |
| cli | `src/tutu_search_flights/cli/` | аргументы, рендер, коды выхода, приёмник событий |

`core` не импортирует `mcp` и `cli`. `mcp` импортирует `core` только ради типов.
Закреплено тестами в `tests/architecture/`.

## Чего делать нельзя

- Ничего не выдумывать. Поля, которого источник не отдал, нет — так и показываем.
- Цена не называется без базы (`party_total`) и без тарифа.
- Пустая выдача не называется отсутствием рейсов, пока счётчики отбора не нулевые.
- Длительности и стыковки — только по моментам, «утро/вечер» — только по местному времени.
- Живая сеть разрешена только `probe.py`. Спека или тест, ходящие в сеть, сломаны
  по определению.
