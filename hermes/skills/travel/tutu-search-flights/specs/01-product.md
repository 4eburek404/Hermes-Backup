# Продуктовая спецификация

Это продуктовый контракт текущего объёма. Фактический охват реализации и
проверок указан в [матрице требований и доказательств](../docs/verification.md);
формулировка поведения сама по себе не объявляет каждое расширение реализованным.

Основание: исследование живого Tutu MCP и сохранённые ответы от 24.09.2026 — [`../docs/mcp-notes.md`](../docs/mcp-notes.md) и [`../fixtures/README.md`](../fixtures/README.md).

```gherkin
Feature: Помощь в поиске авиаперелётов

  Агент помогает человеку искать перелёты в одну сторону или туда-обратно.
  Бронирование не входит в текущий scope.

  Rule: Результаты и сведения о перелёте подтверждаются данными источника

    Scenario: Результаты поиска отражают данные Tutu
      Given человек запросил поиск перелёта
      When агент показывает найденные варианты
      Then сведения о рейсах и перевозчиках соответствуют данным Tutu
      And агент не добавляет неподтверждённые предположения

    Scenario: Отсутствующее значение не подменяется догадкой
      Given в данных источника отсутствует значение о варианте перелёта
      When агент показывает этот вариант
      Then отсутствующее значение не представляется как известный факт

    Scenario: Цена относится к запрошенной группе и своему тарифу
      Given источник указал `party_total` как цену всей запрошенной группы пассажиров для тарифа
      When агент показывает цену этого тарифа
      Then цена остаётся ценой всей группы и не умножается повторно на число пассажиров
      And цена показана вместе с условиями этого тарифа

    Scenario: Время сохраняет локальное время и часовой пояс аэропорта
      Given источник указал время события в локальном времени аэропорта с часовым поясом
      When агент показывает время события
      Then время сохраняет указанное источником локальное значение и часовой пояс

    Scenario: Сообщённая источником длительность сохраняется
      Given источник указал длительность перелёта или пересадки
      When агент показывает этот вариант
      Then длительность соответствует значению, сообщённому источником

    Scenario: Пересадки и сегменты соответствуют данным источника
      Given источник описал вариант перелёта с пересадкой и несколькими сегментами
      When агент показывает этот вариант
      Then пересадка и сведения каждого сегмента представлены без искажения

    Scenario: Сведения о варианте показываются только при подтверждении источником
      Given у сведений о тарифе, багаже, дате или доступности нет подтверждения в данных источника
      When агент показывает вариант перелёта
      Then он показывает только сведения, подтверждённые данными источника

  Rule: Результат поиска не преувеличивает полноту или достоверность выдачи

    Scenario: Недоступные данные не выдаются за отсутствие рейсов
      Given данные поиска не удалось получить
      When агент сообщает человеку результат поиска
      Then он отличает невозможность получить данные от подтверждённого отсутствия рейсов

    Scenario: Причина пустой выдачи от источника или фильтра сохраняется
      Given источник или применённый фильтр объяснил пустую выдачу
      When агент сообщает человеку результат поиска
      Then объяснение пустой выдачи не теряется
      And агент без достаточных оснований не утверждает, что рейсов нет

    Scenario: Следующая страница не позволяет представить выдачу полной
      Given для поиска доступна следующая страница результатов
      When агент показывает результаты текущей страницы
      Then он не создаёт впечатление, что показана вся выдача
```

## Что пока не фиксируется

Внутренние форматы, архитектура, команды и интерфейсы реализации здесь не
предписываются. Вычисление длительности маршрута и стыковок не входит в текущий
контракт; для его добавления потребуется отдельная спецификация.
